# CEL Conformance Coverage

This document tracks conformance test coverage across official CEL runtime
implementations against the
[`cel-spec` simple conformance test suites](https://github.com/cel-expr/cel-conformance/blob/main/tests/simple/testdata).

> **Note:** This matrix is derived from each runtime release's checked-in
> conformance configuration (enabled test files and skip lists), not from
> executed test results. Section totals are computed against each runtime's
> pinned `cel-spec` release (listed in the **Spec Commit** row); suites and
> sections added at newer `cel-spec` revisions are shown as `n/a`, and
> individual tests added to existing sections after a runtime's pin are excluded
> via `absent_tests`.

**Status Legend:**

*   `✅ X/Y`: **Passed** — All `Y` tests in the section are enabled and passing
    (`X == Y`).
*   `❌ X/Y`: **Failed** — One or more tests in the section failed during
    execution.
*   `⚠️ X/Y`: **Skipped** — `X` of `Y` tests pass; the remaining `Y - X` tests
    are explicitly skipped via `skip_tests` (see the `Notes` column and details
    below).
*   `⬜`: **Not Enabled** — The `.textproto` test file is not yet wired into the
    runtime's `_ALL_TESTS` conformance target. When executed in dashboard mode,
    `⬜ (✅ X/Y)` indicates **Passing but Not Enabled**, `⬜ (⚠️ X/Y)` indicates
    **Skipped and Not Enabled**, and `⬜ (❌ X/Y)` indicates **Failing and Not
    Enabled**.
*   `❓`: **Not Run** — Expected `(runtime, config)` column had no test results
    reported.
*   `` `n/a` ``: **Not Applicable** — The suite or section does not exist at the
    `cel-spec` commit tested by that runtime.

### Non-Conforming Suites & Known Issues

> **`network_ext` (Not Enabled)**
>
> *   **Runtimes:** Go (`⬜`), C++ Modern & Legacy (`⬜`), Java (`⬜`)
> *   **Details:** `network_ext.textproto` defines IP/CIDR network extension
>     tests and is present at each runtime's pinned `cel-spec` release, but is
>     not listed in `_ALL_TESTS` for Go, C++, or Java.

> **`lists_ext`, `optionals/optionals`, & `block_ext/basic` optional tests
> (Skipped in C++ Legacy)**
>
> *   **Runtimes:** C++ Legacy (`⚠️`)
> *   **Details:** The legacy C++ evaluator does not implement `lists_ext` or
>     `optional_type`, so `lists_ext/*`, `optionals/optionals`, and the
>     `optional_list`, `optional_map`, `optional_map_chained`, and
>     `optional_message` tests in `block_ext/basic` are skipped.

> **`timestamps/duration_converters` (`getMilliseconds`)**
>
> *   **Runtimes:** Go, C++ (Modern & Legacy)
> *   **Tracking:** [cel-cpp#93](https://github.com/cel-expr/cel-cpp/issues/93)
>     (closed)
> *   **Details:** `timestamps/duration_converters/get_milliseconds` is skipped
>     pending deprecation of `Duration.getMilliseconds` in the spec.

> **`fields/qualified_identifier_resolution` & `namespace`**
>
> *   **Runtimes:** Go, C++ (Modern & Legacy)
> *   **Tracking:** [cel-cpp#97](https://github.com/cel-expr/cel-cpp/issues/97)
> *   **Details:** C++ does not support qualified identifier lookups within
>     containers for parsed-only expressions, though checked expressions pass
>     because the type checker rewrites the identifier
>     (`qualified_identifier_resolution_unchecked` and
>     `namespace/namespace/self_eval_container_lookup_unchecked` force
>     parse-only evaluation); C++ also skips
>     `map_value_repeat_key_heterogeneous`. Go skips `map_key_float`,
>     `map_key_null`, `map_value_repeat_key`, and
>     `map_value_repeat_key_heterogeneous`.
